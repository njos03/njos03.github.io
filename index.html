AI & Agentic

The AI-first development work I have been driving at Conga — what each piece actually is and why it exists.

Bifrost In production

An internal AI agent for the engineering organisation.

An automated knowledge base indexed across internal repositories — system structure, runtime procedures and how to execute tests — so an engineer can ask how something works and get an answer grounded in the actual codebase instead of a guess.

  • AI agent
  • Knowledge base
  • Internal platform
  • Developer enablement

Platform AI MCP server Shipped

One of the first MCP servers built on Conga's new platform AI framework.

Exposes CLM capabilities as Model Context Protocol tools so agents — not just humans — can operate parts of the product lifecycle. Written before there was a formal product requirement, because the point was to find out what the capability was worth.

  • MCP
  • Platform AI framework
  • CLM
  • Prototyping

Developer skills In use

Custom agent skills encoding repeatable internal development workflow.

Rather than leaving AI guidance in wikis nobody reads, the workflow itself is packaged as skills the agent loads on demand — and connected to Jira, Confluence and local test environments over MCP so the agent can act inside the tools we already use.

  • Agent skills
  • MCP
  • Jira
  • Confluence
  • Test environments

Spec-driven development Adopted by the team

OpenSpec and Superpowers skills, used to replace informal design hand-off.

Specs become the source of truth that implementation is checked against, so delivery moves faster without drifting from what was actually agreed. Design compliance stopped being a review-stage argument.

  • OpenSpec
  • Superpowers
  • Spec-driven development
  • Design compliance

Verification harness Evolving

Automated proof of verification for localized and environment-specific QA.

Test execution used to be a manual, environment-shaped chore. The harness encodes it so verification is reproducible and its evidence is produced automatically — cutting regression cycles across locales.

  • QA automation
  • Test harness
  • Localisation
  • Regression

Built on my own initiative and handed to the sales team — a single demonstration of the whole contract lifecycle running through an LLM, which became an input to product decisions before the requirement existed.
